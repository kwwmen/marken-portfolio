# Инструкция по развёртыванию VideoPulse на GitHub Pages

## Шаг 1. Создать репозиторий

1. Зайдите на [github.com](https://github.com) и войдите в свой аккаунт.
2. Нажмите **New repository** (зелёная кнопка справа вверху).
3. Название: `videopulse` (или любое другое).
4. Поставьте галочку **Public** (обязательно для бесплатного GitHub Pages).
5. **Не добавляйте** README, .gitignore и лицензию — проект уже готов.
6. Нажмите **Create repository**.

## Шаг 2. Загрузить файлы

### Вариант A — через веб-интерфейс (проще)

1. Откройте созданный репозиторий.
2. Нажмите **Add file → Upload files**.
3. Распакуйте архив `videopulse-site.zip` на компьютере.
4. Перетащите **всё содержимое папки** в окно GitHub (не саму папку, а файлы внутри).
5. Внизу напишите commit message: `Initial commit`.
6. Нажмите **Commit changes**.

### Вариант B — через Git (если знакомы с командной строкой)

```bash
# Распаковать архив
unzip videopulse-site.zip -d videopulse
cd videopulse

# Инициализировать репозиторий
git init
git add .
git commit -m "Initial commit"

# Привязать к GitHub (замените USERNAME и REPO на свои)
git remote add origin https://github.com/USERNAME/REPO.git
git branch -M main
git push -u origin main
```

## Шаг 3. Включить GitHub Pages

1. В репозитории перейдите в **Settings** (вкладка справа вверху).
2. В левом меню выберите **Pages**.
3. В разделе **Source** выберите:
   - Branch: `main`
   - Folder: `/ (root)`
4. Нажмите **Save**.
5. Через 1–2 минуты вверху появится зелёная плашка с адресом сайта:
   ```
   Your site is live at https://USERNAME.github.io/REPO/
   ```

## Шаг 4. Проверить сайт

Откройте ссылку из предыдущего шага. Если видите белую страницу с заголовком «Карточка, которую досматривают до конца» — всё работает.

**Если видите ошибку 404** — подождите ещё минуту и обновите страницу. Первая сборка может занять до 3 минут.

## Как обновлять работы

### 1. Подготовить файлы

Для каждой новой работы нужны:
- **Видео:** `work-N.mp4` (N — порядковый номер, начиная с 7).
- **Заглушка:** `work-N.webp` — первый кадр видео.

**Сжать видео (обязательно!):**

```bash
ffmpeg -i исходник.mp4 \
  -vf "scale=540:-2,fps=25" \
  -c:v libx264 -profile:v main -crf 30 -preset slow \
  -movflags +faststart -an \
  work-7.mp4
```

**Сделать заглушку:**

```bash
ffmpeg -i work-7.mp4 -vf "scale=540:-2" -frames:v 1 work-7.webp
```

### 2. Загрузить файлы

Через веб-интерфейс GitHub:

1. Откройте репозиторий → папка `assets/video/`.
2. Нажмите **Add file → Upload files** → загрузите `work-7.mp4`.
3. Commit message: `Add work 7 video`.
4. Повторите для `assets/img/posters/` → загрузите `work-7.webp`.

### 3. Обновить JSON

1. Откройте файл `data/works.json` в репозитории.
2. Нажмите карандаш (Edit) справа вверху.
3. Добавьте новый блок **в конец массива, перед закрывающей скобкой `]`:**

```json
  ,
  {
    "id": "work-7",
    "title": "Название товара",
    "category": "Категория",
    "video": "assets/video/work-7.mp4",
    "poster": "assets/img/posters/work-7.webp",
    "description": "Что показано в ролике",
    "duration": 8,
    "demo": false
  }
```

**Важно:**
- Запятая перед блоком.
- `"demo": false` для реальных работ (убирает бейдж «демо»).
- Последний элемент массива **не должен** иметь запятую после себя.

4. Внизу: **Commit changes** → **Commit directly to the main branch**.

### 4. Дождаться сборки

Через 1–2 минуты обновите сайт. Новая работа появится в секции «Работы».

## Как удалить демо-работы

Когда реальных работ станет 6 и больше:

1. Откройте `data/works.json`.
2. Удалите все блоки, где `"demo": true`.
3. Проверьте, что:
   - После последнего элемента массива **нет запятой**.
   - Массив закрывается правильно: `]`.
4. Commit changes.

## Частые проблемы

### Видео не играет

**Причина:** не установлен флаг `+faststart` при сжатии.

**Решение:** пересжать видео командой выше и загрузить заново.

### Видео весит больше 1 МБ

**Причина:** слишком высокое качество или длительность.

**Решение:**
- Укоротить до 10 секунд.
- Поднять CRF до 32: `-crf 32` вместо `-crf 30`.

### Сайт открывается, но видео не видны

**Причина:** видео лежат не в `assets/video/`.

**Решение:** проверить пути в `data/works.json` — они должны совпадать с реальными.

### JSON не сохраняется, выдаёт ошибку

**Причина:** где-то лишняя или недостающая запятая, скобка или кавычка.

**Решение:** вставить содержимое в [jsonlint.com](https://jsonlint.com) — он покажет строку с ошибкой.
